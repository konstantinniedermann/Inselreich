# I-049 Sperrbestand Implementation Plan (Reserve je Insel für Holz und Stein)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Ziel:** Der Spieler setzt im Handelsdialog des Kontors je Insel eine Reserve für Holz und Stein (0/20/40/60). Betriebe mit `consumes` entnehmen ein Reserve-Gut nur noch, solange `stock > reserve`; sonst Zustand `waitingReserve`. Bauen, Ausbau, Aufstieg, Handel, Fest, Haushalt und Schiffsladung bleiben frei. Alle Reserven 0 = bitgleich zu heute.

**Grundlage:** Kurzdesign `docs/superpowers/specs/2026-10-10-i049-sperrbestand-design.md` (`7e6b2844`, AK-SB-01…17, Wortlaut dort), Ruling **R477** (E1 je Insel, E2 nur Holz/Stein, E3 Schiffsladung nicht, E4 keine Problemliste; Save-Reihenfolge M13-E2 = v12). Stufe **leicht** (Plan im kombinierten Gate), Planbasis `main` @ `753c0067`, `SAVE_VERSION` 11. Arbeiter lesen nur ihre Task und die genannten AK im Kurzdesign.

**Nachtrag M13-E2 (R489 tech B5, R507 E8):** vor T01 einarbeiten — [nachtrag-i049.md](2026-10-11-m13-e2-denkmal/nachtrag-i049.md) (Fall K1, `dropZeroReserve`, Save v12 Fall A).

## Architektur (≤ 15 Zeilen)

1. `src/sim/defs/reserve.ts` (neu): `RESERVE_GOODS = ['wood','stone']`, `RESERVE_STEPS = [0,20,40,60]`, Typ `ReserveGood`, `ReserveStep`.
2. `types.ts`: `BuildingState` + `'waitingReserve'`; `Island.reserve: Record<ReserveGood, ReserveStep>` (nach `anchor`, immer vollständig). `world.ts` (Heimat) und `save.ts` (`foreignIslands`, `migrateV7ToV8`-Fremdinseln) legen `{ wood: 0, stone: 0 }` an.
3. `production.ts` `advance`: nach dem `waitingInput`-Zweig: `if (def.consumes.some(g => stock[g] <= reserveOf(island, g))) { state='waitingReserve'; return false }`, danach Entnahme. `reserveOf(island, g)` = Inselwert für Holz/Stein, sonst 0 (reiner Helfer in `queries.ts` oder `production.ts`, ein Ort).
4. `queries.ts`: `reservedInputs(world, b)` (Güter mit `1 ≤ stock ≤ reserve`, Reihenfolge `consumes`), `reserveHolds(world, island, good)` (Anzahl Betriebe der Insel in `waitingReserve` mit `good` in `consumes` und `stock ≤ reserve`, für den Zusatz «hält n Betriebe an»).
5. Neues Modul `src/sim/reserve.ts`: `setReserve(world, island, good, value): Result` (fünf Fälle R4; Kontor-Absage mit dem Text von `noKontorTrade`). Kein Tick-Eingriff, keine Sperrzeit, in der Pause erlaubt.
6. `save.ts`: `BUILDING_STATES` + `'waitingReserve'`, Inselprüfung (`reserve` Objekt mit genau `wood`,`stone`, Werte aus `RESERVE_STEPS`, sonst `{ ok: false }`), Migration (siehe Task-Weiche T03).
7. UI (nach Sim): `trade.ts` Reserve-Zeile in den Zeilen Holz/Stein (−/+ wie `ships.ts`-Routenreserve, Zusatz «hält n Betriebe an», Tooltip); `TradeActions.reserve(good, value)`; `texts.ts` (`stateInfo`), `hover.ts`, `guide.ts` (`remedyText`), `panelView.ts` (Ton `warn`), `goodFocus.ts` nur über `stateInfo` (kein Code erwartet, Test); `problems.ts` bewusst ohne Zweig (AK-SB-14, Test); `statusMarks.ts` unverändert (`null`, Test AK-SB-17); `daynight.ts` nur Kommentar der dunklen Zustände.

- **Rückfaltung und Golden-Hashes:** `helpers.ts` (`foldBackToV9/V10`) und E2 `foldBackToV11` müssen `reserve` verwerfen; vergessene Stelle lässt `seaGolden`/`edicts` rot werden (sichtbar, früh).
- **Prüfreihenfolge:** `waitingReserve` darf `waitingInput` nie überdecken (AK-SB-04, 05) und nie vor `paused` stehen (AK-SB-08); `eff` zählt 0.
- **Stale Zustand:** Nach `setReserve` bleibt der Betriebszustand bis zum nächsten Tick alt (Anzeige verzögert um höchstens einen Tick, bewusst, wie bei Stilllegen-Rückkehr).
- **Spielwirkung:** Reserve 60 bei schwacher Holzerzeugung legt Werkzeug und Glas still, sichtbar über Zusatz und Fokus (Kurzdesign 4); kein Balancing-Eingriff.
- **Dialogbreite:** Reserve-Zeile im Handelsdialog bei 1280 px (Boom-Marke, Lager, Preis, Zusatz in der Namenszelle); Fallback: Zusatz in zweite Zeile unter den Namen (Browser-Check SB-16).
- **Doku-Hot-Spot:** arc42-Zeile `save.ts` und README teilen sich E2, I-048, UI-TASTEN; T07 Schritt 0 `main` mergen.

## Entwürfe an L0

- Fall A/B/C der Save-Weiche beim Abzweig von T03 (Release-Stand von v12) und die Merge-Reihenfolge M13-E2-SIM vor I-049-Sim. Empfehlung: Fall A, falls M13-E2 und I-049 in dasselbe Release gehen, sonst B. Kein neues Ruling jetzt nötig.
- Hinweis an E2-Spec-Autor: `foldBackToV11` und AK-M13E2 «Rückfaltung» kennen `Island.reserve` (Fall A) bzw. nicht (Fall B, I-049 danach).
